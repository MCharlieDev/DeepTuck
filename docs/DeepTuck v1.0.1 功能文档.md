# DeepTuck v1.0.1 功能文档

> 记录日期：2026-11-08
> 适用版本：`manifest.json` 中 `version = 1.0.1`
> 目标站点：`https://chat.deepseek.com/*`

---

## 一、项目概述

DeepTuck 是一个 Manifest V3 浏览器扩展，用于优化 DeepSeek 网页版的内容阅读体验，核心能力：

1. 自动折叠 AI 的“思考过程”
2. 长回答超过 240px 时折叠，并提供“展开全文 / 收起”
3. 限制输入框高度，避免长文本把输入框无限撑高
4. 同时适配普通聊天页、分享选择界面和只读分享页

---

## 二、文件与权限

| 文件 | 作用 |
| --- | --- |
| `manifest.json` | MV3 配置，匹配 `https://chat.deepseek.com/*` |
| `content.js` | 页面注入逻辑：折叠、状态管理、滚动锚定 |
| `style.css` | 全部视觉样式：遮罩、按钮、输入框限高 |
| `popup.html` / `popup.js` | 全局启用/关闭开关，状态存 `chrome.storage.local` |
| `docs/` | 重构纲要与 DeepSeek DOM 样式细节记录 |

权限：`storage`、`activeTab`。

## 三、功能清单

### 1. 思考过程折叠

- 通过 `.ds-think-content` 判断是否存在思考正文。
- **最终方案：CSS 预折叠**
  - 所有 `.ds-think-content` 在挂载时由 CSS 直接 `display: none`，历史与最新思考块全部自动折叠。
  - 内容不参与布局，虚拟列表测量到的就是折叠后高度，因此上滑挂载历史消息时不会再改高度。
  - 原生“已思考”标题点击被捕获拦截，由 `.deeptuck-think-open` 类控制展开/收起。
  - 展开时才 `display: block`，并做一次视口锚定，同时重新定位正文折叠按钮。
  - 如果站点自身处于折叠态（思考正文不存在），放行首次点击让站点展开，下一帧再接管显示。
- 原生标题箭头方向由 CSS 控制：收起朝右、展开朝下。
- 分享选择界面的思考标题后缀哈希变化（如 `_245c867 a51c5344`）仍可通过主类名 `_245c867` 命中。

### 2. 长正文折叠

- 仅处理 `.ds-markdown.ds-assistant-message-main-content`，不会误伤思考正文和用户消息。
- **B 方案：挂载即限高**
  - CSS 对所有 assistant 正文在挂载时就应用 `max-height: 240px` 和 `overflow: hidden`。
  - 虚拟列表测量到的就是折叠后的高度，不会出现“挂载时全高、随后变 240px”的突变。
  - JS 只负责判断 `scrollHeight > 240` 并添加 `.deeptuck-folded`（渐隐）和按钮，不再等待免责声明。
  - 流式输出也会立即限高；超过 240px 后按钮出现，可随时展开。
- 展开按钮：
  - 追加到消息末尾，使用绝对定位覆盖在正文底部（`top/left` 由 JS 按正文位置计算）。
  - 固定高度 28px，不参与布局，**不增加消息高度**。
  - 展开、收起、思考块展开/收起、窗口 resize 时都会重新计算位置。
  - 视觉对齐原生“已思考”标题：小号弱化文字 + 旋转箭头。
  - 折叠态箭头朝右，展开态箭头朝下。
- 展开/收起通过 `.deeptuck-expanded` 类名切换，按钮文案和 `aria-expanded` 同步。

### 3. 输入框限高

- 只给 `textarea[name="search"]` 加 `.deeptuck-composer` 类名。
- 纯 CSS 限制 `max-height: 160px` 和 `overflow-y: auto`，不依赖父级结构。
- 隐藏官方 `.ds-scroll-area__gutters`（其高度按未限高的 `--container-height` 绘制），改用 textarea 自身细滚动条。

### 4. 页面类型适配

| 页面 | 行为 |
| --- | --- |
| 普通聊天页 | CSS 挂载即限高；最新回答自动折叠思考块；输入框限高 |
| 分享选择界面 | `--printable` 页面同样从挂载即限高；按钮覆盖在正文底部；不依赖免责声明 |
| 只读分享内容 | 正文可能带 `pointer-events-none`，按钮单独恢复 `pointer-events` |

分享选择界面的额外处理：

- 页面可能强制展开所有正文，已用高优先级 `!important` 规则从挂载开始就把高度压回 240px。
- 页面会把消息内元素的指针事件设为 `none`，按钮使用内联 `pointer-events: auto !important` 兜底。
- 按钮使用 `position: relative; z-index: 2` 抬到选择热区之上。
- 按钮使用 `flex: 0 0 auto; align-self: flex-start`，避免被父级 flex 拉满高度。

### 5. 状态与容错

- 不使用 `data-deeptuck-*` 属性，全部状态保存在内存：
  - `processedMessages`：已处理的消息
  - `thinkOpenMessages`：用户手动展开过思考块的消息
  - `foldedContents`：曾折叠过的正文
  - `messageIdentity`：消息 → 虚拟列表 key
- 虚拟列表节点被销毁后，`WeakSet` / `WeakMap` 随节点回收；节点重建后会重新处理。
- 通过 `data-virtual-list-item-key` 识别节点复用，key 变化时清理旧产物并重新处理。
- React 重置 `className` 抹掉 `.deeptuck-folded` 时，属性观察器会自动补回类名和按钮状态。
- React 重置消息类名时，会恢复用户手动展开的 `.deeptuck-think-open`。
- 按钮被抹掉时，`artifactsLost` 会触发重新折叠并补按钮。
- 子节点被移除（例如 React 抹掉按钮）时，也会重新检查所属消息，避免按钮永久丢失。
- 正文的 240px 限高由 CSS 在挂载时应用，思考正文默认隐藏；JS 注入的类名和按钮不会改变 item 高度。
- 单条消息处理异常会被隔离，并输出 `[DeepTuck] processMessage failed:` 警告，不影响其它消息。

### 6. 视口锚定（防折叠弹跳）

折叠会减少消息高度，导致视口内容上移。当前实现：

1. `getScrollParent()` 找到真正负责纵向滚动的祖先容器。
2. `pickViewportAnchor()` 选择当前视口中“顶部位于视口内或下方”的第一条消息作为锚点。
3. 折叠/展开前记录锚点的 `getBoundingClientRect().top`。
4. 布局变化后按差值调整 `scrollTop`，把锚点拉回原位置。
5. 下一帧再校正一次，兼容虚拟列表重算。
6. 已应用到手动正文展开/收起、思考块展开/收起、关闭插件时的全局展开。
7. 已移除 `max-height` 过渡动画，避免滚动补偿滞后。
8. 历史正文与思考块都由 CSS 在挂载时折叠，不再在挂载后改高度，因此上滑抖动的主来源已被移除。

### 7. 开关

- popup 开关写入 `chrome.storage.local` 的 `deeptuck_enabled`。
- 关闭时：
  - 断开 MutationObserver
  - 取消待执行的 rAF
  - 移除所有 `.deeptuck-folded` / `.deeptuck-expanded` / 按钮 / 输入框类名
  - 展开内容时同样做视口锚定

## 四、这几轮改动记录

### 第 1 轮：整体重构

- 抛弃 `data-deeptuck-*`，改用 `WeakSet` / `WeakMap`。
- 用 `mask-image` 替代 JS 插入遮罩 `div`。
- 按钮移出 `.ds-markdown`，改为正文之后插入。
- 输入框只加类名，纯 CSS 限高。
- 精准选择器替代全局 `span` 扫描和 `parentElement.parentElement`。

### 第 2 轮：按钮视觉与布局

- 按钮改为原生“已思考”风格：12px 弱化文字 + 箭头 + 悬停浅底。
- 箭头状态与原生一致：折叠朝右、展开朝下。
- 按钮放在每条对话末尾，不覆盖也不进入原生底部操作栏。
- 隐藏输入框上方按 `--container-height` 绘制的滚动条槽。

### 第 3 轮：分享选择界面适配

- 新增 `._0fcaa63` 免责声明和“内容由 AI 生成 / 请仔细甄别”文案兜底。
- 新增 `.ds-virtual-list--printable` 只读快照判定，无免责声明也能折叠。
- 按钮统一追加到 `.ds-message` 末尾，有/无原生操作栏都能落位。

### 第 4 轮：分享页强制展开、热区与类名重置

- 分享页强制展开：增加高优先级 `!important` 折叠规则。
- 按钮被热区覆盖：增加 `z-index`、`align-self`、`flex` 约束。
- 按钮 `pointer-events: none`：改为内联 `pointer-events: auto !important` + 高优先级 CSS。
- React 重置类名：MutationObserver 增加 `class` 属性监听并自动恢复折叠态。

### 第 5 轮：折叠时视口弹跳

- 新增滚动容器识别、视口锚点选择、滚动快照与恢复。
- 自动折叠与手动展开/收起均接入锚定。
- 移除 `max-height` 过渡，避免高度变化与滚动补偿不同步。

### 第 6 轮：版本与仓库

- `manifest.json` 版本重置为 `1.0.0`。
- `content.js` / `style.css` 头部版本改为 `v1.0.0`。
- 初始化 git 仓库并推送：
  - 仓库：`https://github.com/MCharlieDev/DeepTuck.git`

  - 视口锚定修复提交：`08b7c5b fix: 折叠时锁定视口位置，避免用户窗口弹跳`

### 第 7 轮：B 方案，修复上滑时虚拟列表抖动

- 问题定位：
  - 关闭插件后上滑不再抖动，说明是我们的高度修改触发。
  - 短对话没有长正文折叠却仍抖动，进一步定位到“已思考”思考块。
  - 思考块在虚拟列表卸载/重挂载后会恢复默认展开，我们的自动点击在挂载后再次折叠，反复改变 item 高度。
- 修复：
  - CSS 对所有 assistant 正文挂载即限高 240px，虚拟列表测量到的就是折叠后高度。
  - CSS 对所有 `.ds-think-content` 挂载即隐藏，思考块不再依赖挂载后点击。
  - JS 只负责加渐隐和按钮，不再等免责声明，也不再在挂载后改变正文/思考块高度。
  - 按钮追加到消息末尾并绝对定位覆盖在正文底部，不增加 item 高度。
  - 原生“已思考”标题点击由扩展接管，用 `.deeptuck-think-open` 控制展开/收起，展开时才显示内容。
  - 子节点移除时重新检查所属消息，避免 React 抹掉按钮后永久丢失。

## 五、已验证内容

使用本地 mock 页面 + 无头 Chrome 验证：

1. 正文在挂载时就被 CSS 限高到 240px，长回答不再出现“挂载后再变矮”。
2. 所有思考正文默认 `display: none`，历史与最新思考块都会自动折叠。
3. 长正文按钮绝对定位、高度 28px，按钮底边与正文底边对齐，免责声明位置不变（item 高度不增加）。
4. 点击原生“已思考”标题可展开思考正文，再次点击可收起；展开/收起时按钮位置同步更新。
5. 点击“展开全文”后正文解除限高，渐隐消失，按钮保持在正文底部；再次点击恢复 240px 和渐隐。
6. 分享选择界面强制展开规则被更高优先级压回 240px，思考正文默认隐藏。
7. 分享页正文 `pointer-events: none` 时，按钮仍可点击。
8. 折叠视口上方的消息时，当前可见消息位移约 `-0.41px`，滚动位置自动补偿。

注意：无头 Chrome 的 rAF 会被节流，滚动锚定测试使用了定时器调度的测试副本；生产代码逻辑一致。

## 六、尚未完成 / 已知缺陷

### P0：B 方案的已知代价

1. **可见回答与流式回答从挂载起就被限高到 240px**
   - 现象：正在生成的回答也会立即被裁剪，超过 240px 后按钮出现，需要手动展开才能继续看尾巴。
   - 这是 B 方案保证虚拟列表高度稳定的直接代价。
   - 待做：如果官方有可靠的“正在生成”状态，可只对当前生成中的回答临时不预折叠，完成后再折叠并做锚定；否则保持现状。

2. **原生思考标题点击被扩展接管**
   - 站点内部思考状态保持展开，由 `.deeptuck-think-open` 控制显示。
   - 如果站点通过其它方式移除/重建思考正文，依赖下一帧接管显示，存在时序风险。
   - 若站点在 capture 阶段处理标题点击，扩展的拦截可能失效或双重触发。
   - 待做：用真实页面验证；必要时调整事件监听层级。

### P1：稳定性与兼容性

3. **选择器依赖哈希类名**
   - 依赖 `_245c867`、`_34a54ec`、`.ds-think-content`、`.ds-virtual-list--printable` 等。
   - 部分有结构/文字兜底，但思考标题和分享列表仍强依赖类名。
   - 待做：持续收集新版 DOM，集中到配置区。

4. **注入产物仍在 React 管理的 `.ds-message` 内**
   - React 重渲染可能移除按钮或重置类名；已有属性监听、子节点移除检查和 `artifactsLost` 补救。
   - 待做/评估：把按钮挂到消息外层稳定容器，彻底脱离 React 子节点管理。

5. **分享页按钮指针事件使用内联 `!important`**
   - 这是对页面只读限制的应急绕过。
   - 如果官方改用其它方式禁用交互，可能再次失效。
   - 待做：运行时检查 `pointer-events`，必要时动态兜底。

6. **热区层级只验证了常见结构**
   - `z-index: 2` 可能被更高层级或独立堆叠上下文覆盖。
   - 待做：出现点击穿透时，用 `elementsFromPoint` 动态测量覆盖层并提高层级或移出容器。

7. **滚动锚定只校正一次 + 下一帧**
   - 图片/字体懒加载、虚拟列表二次测量可能继续改变高度。
   - 待做：ResizeObserver 或多次稳定检测；也可评估原生 `overflow-anchor`。

8. **多滚动容器未覆盖**
   - `stop()` 只取第一个正文所在滚动容器。
   - 多面板、嵌套滚动区域可能出现未补偿的位移。

9. **按钮覆盖正文底部 28px**
   - 按钮绝对定位覆盖在正文渐隐区，不增加高度，但可能遮挡最后一行文字或链接。
   - 待做：观察真实页面；必要时缩小覆盖高度或给按钮加背景。

10. **绝对定位按钮依赖布局计算**
    - `top/left` 基于正文相对消息的位置；消息内部重排（标题、脚注等变化）可能造成偏移。
    - 当前在展开/收起、思考开关、窗口 resize 时重新定位；站点其它未观察的重排可能漏掉。
    - 待做：用 ResizeObserver 监听正文/消息尺寸变化，自动重定位。

11. **手动展开状态不会跨虚拟列表重挂载保留**
    - 正文展开和思考展开都会在消息被销毁重建后回到默认折叠（由 CSS 预折叠决定）。
    - 待做：如需要，可按消息 key 持久化展开状态，但仍要解决“挂载后应用状态会改高度”的问题。

12. **CSS 预折叠可能被官方更强规则覆盖**
    - 分享选择界面的强制展开已用高优先级规则压住；其他页面若使用更高优先级或内联 `!important`，仍可能失效。
    - 待做：在 `foldContent` 中检测 `computed max-height`，必要时用内联 `!important` 兜底。

### P2：体验与工程化

13. **按钮文案为中文**
    - 思考块折叠已不再依赖“已思考”文字匹配。
    - 展开/收起按钮仍显示中文“展开全文 / 收起”，英文界面未做适配。

14. **思考块展开依赖站点保留正文 DOM**
    - 我们的方案依赖站点在展开态时保留 `.ds-think-content`。
    - 如果站点改成按需渲染/移除思考正文，展开逻辑需要调整。

15. **输入框高度固定为 160px**
    - 没有可配置项，也没有多档高度选择。
    - 隐藏 gutter 使用 `:has()`，仅 Chromium 支持（当前 MV3 目标可用）。

16. **无自动化测试**
    - 依赖 mock 页面 + 无头 Chrome 手工验证。
    - 没有正式测试用例，官方改版后的回归风险较高。

17. **文档版本不一致**
    - `docs/DeepTuck 重构纲领.md` 仍写 `v4.0 规划`，与当前 `v1.0.0` 功能文档不一致。
    - 待做：统一版本口径或标注为历史规划。

18. **性能开销**
    - MutationObserver 监听全页 `class` 变化（虽只做轻量匹配）。
    - 思考块处理会在消息内扫描 `span`，超长对话仍有开销。

19. **可访问性**
    - 按钮有 `aria-expanded`，但没有键盘快捷键或焦点管理。
    - 预折叠可能在屏幕阅读器中造成上下文跳变。

20. **发布流程未完成**
    - 尚无 README、商店截图、更新日志、打包产物。
    - 第 7 轮 B 方案改动已随 `v1.0.1` 提交。
