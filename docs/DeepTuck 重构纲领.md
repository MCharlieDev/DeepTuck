# 🚀 DeepTuck 重构纲领 (v1.0.0 规划)

## 一、 重构目标 (Why)
1. **解决稳定性隐患**：杜绝因直接向 React/Vue 托管的 DOM 节点中插入元素，导致的页面崩溃、渲染错乱或节点被抹除的问题。
2. **提升运行性能**：优化 `MutationObserver` 的监听策略，减少全量 DOM 遍历，降低长对话页面的 CPU 和内存占用。
3. **增强代码健壮性**：弱化对特定文本（如“已思考”）和脆弱 DOM 层级（如 `parentElement.parentElement`）的硬编码依赖，增加容错机制。
4. **提升可维护性**：实现 JS 逻辑与 CSS 样式的彻底解耦，采用更现代的状态管理，让代码结构更清晰。

## 二、 核心原则 (How)
* **最小侵入原则**：只做“观察者”和“修饰者”，尽可能不破坏 DeepSeek 页面原有的 DOM 树结构。
* **防御性编程**：所有的 DOM 查询和操作都必须考虑“找不到节点”的降级处理，绝不抛出阻断性异常。
* **CSS 优先**：能用 CSS 解决的视觉效果（如渐隐遮罩、高度限制、动画过渡），坚决不用 JS 插入 DOM 来实现。
* **内存安全**：引入 `WeakSet` / `WeakMap` 管理节点状态，避免内存泄漏和 DOM 属性污染（清理 `data-xxx`）。

## 三、 分阶段实施计划 (What & When)

### 阶段一：DOM 结构解耦与样式重构 (视觉与 UI 层)
* **正文折叠（核心痛点）**：
  * *旧*：JS 动态创建 `.deeptuck-mask` 渐变层和 `.deeptuck-btn` 塞入 `.ds-markdown` 内部。
  * *新*：改用 CSS `mask-image` 或伪元素实现底部渐隐；按钮**移出正文容器**，利用相对定位挂载在消息外层容器上。
* **输入框限制**：
  * *旧*：强依赖 `parentElement.parentElement` 向上找容器。
  * *新*：寻找更稳定的特征容器（如包裹 textarea 的特定 class 或 ID），或直接通过 CSS 属性选择器配合 `:has()` 实现高度限制。
* **清理行内样式**：移除 JS 中的 `style.cssText`，所有样式统归 `style.css` 管理。

### 阶段二：性能与状态管理优化 (逻辑与性能层)
* **精准监听**：
  * *旧*：全量 `document.querySelectorAll('span')`。
  * *新*：缩小查询范围（如只在 `[role="button"]` 中找，或监听特定 DOM 变化事件）。
* **无痕状态管理**：
  * *旧*：大量使用 `dataset`（如 `data-deeptuck-folded`）标记节点。
  * *新*：引入 `WeakSet` 在内存中记录已处理的节点，实现真正的“无痕”。
* **节流/防抖**：保留并优化 `requestAnimationFrame` 的调用逻辑，确保高频 DOM 变动下不卡顿。

### 阶段三：健壮性与多语言支持 (容错与体验层)
* **文本匹配降级**：
  * *旧*：死板匹配 `'本回答由 AI 生成'`。
  * *新*：提取配置，支持正则，兼容英文界面或其他变体。
* **状态恢复保障**：
  * 确保插件关闭或刷新时，所有注入的类名、修改过的内联属性、隐藏的滚动条等都能 100% 恢复原状。

### 阶段四：工程化与发布准备 (维护层)
* **代码规范**：引入 ESLint/Prettier，统一代码格式。
* **文档完善**：编写标准的 `README.md`，添加项目截图、安装指南和更新日志（Changelog）。
* **打包方案**：考虑是否需要构建工具（如 Rollup/Vite）把代码打包得更紧凑（当前纯原生 JS 也可以，视需求而定）。

---

## 四、 预期成果
重构完成后，项目将拥有一个**干净、解耦、高性能**的架构，能够快速适应 DeepSeek 官方的 UI 调整，并为未来扩展新功能（如多主题支持、快捷键操作等）打下基础。
