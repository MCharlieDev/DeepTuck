# DeepTuck v1.0.1 修改记录

> 版本：`1.0.1`
> 基线版本：`1.0.0`
> 记录日期：2026-11-08
> 目标站点：`https://chat.deepseek.com/*`

---

## 一、本次修复的核心问题

v1.0.0 在长对话中向上滚动时会出现连续快速的视口弹跳，内容会被拉向最后一两条消息。定位结果：

1. 关闭 DeepTuck 后不再弹跳，说明触发源是扩展对 DOM 高度的修改。
2. 没有长正文折叠的短对话仍会弹跳，进一步定位到“已思考”思考块。
3. 思考块在虚拟列表卸载/重挂载后会恢复默认展开；扩展在挂载后点击折叠，反复改变 item 高度。
4. DeepSeek 的虚拟列表因此反复重新测量总高度、修正滚动位置，造成快速抖动。

v1.0.1 的目标：**历史和新消息的思考块、正文都自动折叠，同时不修改虚拟列表挂载后的 item 高度。**

---

## 二、与 v1.0.0 的主要差异

### 1. 思考块改为 CSS 预折叠

- 所有 `.ds-think-content` 在挂载时由 CSS 直接 `display: none`。
- 思考正文不参与布局，虚拟列表测量到的就是折叠后的高度。
- 不再在消息挂载后自动点击思考标题。
- 原生“已思考”标题点击由扩展接管：
  - 使用 `.deeptuck-think-open` 控制展开/收起。
  - 展开时才 `display: block`，收起时恢复隐藏。
  - 展开/收起前后做视口锚定，并重新定位正文按钮。
- 箭头方向由 CSS 控制：收起朝右、展开朝下。

### 2. 正文改为挂载即限高

- CSS 对所有 `.ds-markdown.ds-assistant-message-main-content` 在挂载时应用 `max-height: 240px` 和 `overflow: hidden`。
- 长回答不再出现“挂载时全高、JS 随后改成 240px”的高度突变。
- JS 只负责：
  - 判断 `scrollHeight > 240`
  - 添加 `.deeptuck-folded` 渐隐
  - 创建展开按钮
- 不再等待免责声明或回答完成。

### 3. 展开按钮改为绝对定位、零布局高度

- 按钮追加到消息末尾，使用绝对定位覆盖在正文底部。
- `top/left` 由 JS 按正文相对消息的位置计算，固定高度 28px。
- 按钮不参与布局，**不增加消息高度**。
- 展开、收起、思考块展开/收起、窗口 resize 时都会重新定位。
- 保留零高度、层级和 `pointer-events: auto !important`，分享只读页仍可点击。

### 4. 恢复底部渐变蒙版

- `.deeptuck-folded` 重新应用 `mask-image`：
  `linear-gradient(to bottom, #000 calc(100% - 64px), transparent 100%)`。
- 长正文折叠后重新出现底部渐隐。

### 5. 容错增强

- React 重置消息类名时，恢复用户手动展开的 `.deeptuck-think-open`。
- React 重置正文类名时，恢复 `.deeptuck-folded`。
- 子节点被移除（例如 React 抹掉按钮）时，重新检查所属消息，避免按钮永久丢失。

### 6. 移除输入框高度限制（阉割）

- 输入框限高在真实页面存在交互/布局 bug，v1.0.1 直接移除该能力。
- 不再给 `textarea[name="search"]` 添加 `.deeptuck-composer` 类名。
- 不再设置 textarea 的 `max-height`、滚动条样式，也不再隐藏 `.ds-scroll-area__gutters`。
- DeepSeek 输入框恢复原生高度行为，扩展不再干预。

## 三、行为变化与已知代价

1. **所有历史的思考块和长正文都会自动折叠**，包括上滑重新挂载的旧消息。
2. 正在流式生成的回答也会从开始就限高在 240px；超过 240px 后按钮出现，可手动展开。
3. 用户手动展开的正文/思考块状态不会跨虚拟列表重挂载保留，消息重建后回到默认折叠。
4. 原生思考标题点击被扩展接管，站点内部思考状态保持展开，显示与否由 `.deeptuck-think-open` 控制。
5. 按钮绝对定位依赖正文相对消息的位置；消息内部未观察到的重排可能造成偏移，已在展开/收起、思考开关和 resize 时重新定位。
6. 分享选择界面仍使用高优先级 `!important` 压住官方的强制展开规则。
7. 输入框高度限制已移除，恢复 DeepSeek 原生输入框行为。

## 四、验证结果

使用本地 mock 页面 + 无头 Chrome 验证：

1. 4 条长回答 + 4 个默认展开的思考块：
   - 4 个思考正文全部 `display: none`
   - 4 个正文全部 `max-height: 240px`、`folded: true`
   - 4 个按钮：绝对定位、高度 28px、按钮底边与正文底边对齐
   - 免责声明位置不变，按钮未增加 item 高度
   - 渐隐蒙版存在
2. 点击“已思考”：思考正文从 `none` 变为 `block`，再次点击恢复 `none`；按钮位置同步更新。
3. 点击“展开全文”：正文 `max-height` 变为 `none`、渐隐消失；再次点击恢复 `240px` 和渐隐。
4. 分享选择界面：
   - 官方强制展开规则被压回 240px
   - 思考正文默认隐藏
   - 正文 `pointer-events: none` 时按钮仍可点击
5. 折叠视口上方的消息时，当前可见消息位移约 `-0.41px`，滚动位置自动补偿。
6. 输入框不再被扩展修改：无 `.deeptuck-composer` 类名，无 `max-height` / 滚动条覆盖。

## 六、已知问题

详细清单见 `docs/DeepTuck v1.0.1 功能文档.md` 第六节，当前重点：

- 流式回答从开始就被限高 240px。
- 原生思考标题点击被接管，站点重渲染思考正文时存在时序风险。
- 按钮绝对定位依赖布局计算，站点未观察到的重排可能造成偏移。
- 历史/手动展开状态不跨虚拟列表重挂载保留。
- 绝对定位按钮覆盖正文底部 28px，可能遮挡最后一行文字或链接。
